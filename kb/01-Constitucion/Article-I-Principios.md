# Artículo I — Principios Fundamentales


Los **15 principios** (P-01..P-15) que definen la filosofía arquitectónica de todo el arnés:

| Principio | Enunciado (traducción) |
|-----------|----------------------|
| P-01 | El contexto es un componente arquitectónico de primera clase |
| P-02 | El modelo es reemplazable |
| P-03 | Las tools son capabilities explícitas, no trucos de prompt |
| P-04 | Toda acción produce eventos observables |
| P-05 | Los side effects pasan por policy |
| P-06 | Los agentes son configuración sobre un runtime compartido |
| P-07 | Las skills codifican conocimiento procedural reutilizable |
| P-08 | Agent state y session state son preocupaciones distintas |
| P-09 | La confiabilidad de un solo agente precede a la complejidad multi-agente |
| P-10 | El harness posee el estado de ejecución — no el modelo |
| P-11 | La UI es un adapter, no parte del core |
| P-12 | Los eventos observan; los hooks intervienen |
| P-13 | La autorización es determinística y externa al LLM |
| P-14 | El contexto se selecciona, no se vuelca |
| P-15 | Automatización y agentes comparten el mismo sustrato de ejecución |

**Los tres que más citan los componentes:** P-05 (side effects por policy), P-10 (el harness posee el estado) y P-13 (autorización determinística externa).
